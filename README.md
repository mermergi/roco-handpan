# 手碟自动演奏 (Handpan Autoplay)

一个独立安装的 Android 自动化 APP：**导入音乐文件 → 自动解析成音符 → 按校准好的琴键坐标自动弹奏游戏里的手碟**。

不需要 root，不需要电脑，不需要 adb。整个 APP 在一台 Android 手机上构建完成（Termux + aapt2 + d8 + apksigner）。

---

## 1. 安装

```bash
termux-open /data/data/com.termux/files/home/deepseek-harness-termux/handpan-app/handpan-autoplay.apk
```

或者用文件管理器打开 `handpan-app/handpan-autoplay.apk`。

安装时系统可能提示「未知来源」，允许即可。

## 2. 首次配置（三步，缺一不可）

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① 悬浮窗权限 | 打开 APP → 点【授予悬浮窗权限】→ 允许 | 校准层和「停止」按钮要盖在游戏上 |
| ② 无障碍服务 | 点【开启无障碍服务】→ 在列表找到「手碟自动演奏」→ 打开 | **这是能自动点屏幕的关键**。本服务不读取任何屏幕内容 |
| ③ 校准琴键 | 点【校准琴键】→ 切到游戏 → 按提示依次点**9 个键**的正中心：上排 `高音1 高音2 高音3`、中排 `中音3 中音4 中音5 中音6 中音7`、下排 `低音6` | 点完自动结束 |

> ⚠️ 如果打开无障碍时弹出「受限设置」/「限制设置」，点系统菜单里的**允许受限设置**（Android 13+ 对侧载应用的默认限制）。
>
> ⚠️ 小米/HyperOS 可能还需要在 设置 → 应用管理 → 手碟自动演奏 里额外允许「自启动」和「后台弹出界面」。

## 3. 使用流程

```
选择音乐文件 → 确认解析结果（会自动显示前 80 个音符的简谱数字）
            → 点【试弹一遍】确认 9 个坐标都对
            → 点【开始演奏】→ 5 秒内切到游戏 → 自动弹奏
```

演奏中屏幕左上角有悬浮【■ 停止】按钮，可拖动，点一下立即停止。

## 4. 支持的输入格式

| 格式 | 解析方式 | 精度 |
|---|---|---|
| **MIDI**（`.mid`） | 直接解析音符事件、tempo 变化、多轨、running status | ⭐ 最高，推荐 |
| **简谱文本**（`.txt`） | 直接读数字，无需识别 | ⭐ 高 |
| **音频**（`.wav` / `.mp3` / `.m4a` / `.ogg` / `.flac`） | 解码成 PCM → YIN 音高检测 → 音符分段 | 一般，单音旋律才准 |

简谱文本写法：

```
1 1 5 5 6 6 5- 4 4 3 3 2 2 1-
```
- `1`~`7` = 音级（do~si），`0` = 休止
- 后面的 `-` 每多一个延长一拍；`_` 表示八分音符（`1_`），`__` 表示十六分
- `|` 忽略，`%` 之后是注释

示例文件已放在 **`/sdcard/Download/handpan-samples/`**：
`twinkle.mid`、`twinkle.wav`、`twinkle.txt`（同一首《小星星》，可用来对比三条解析路径）。

## 5. 关键设计（为什么这么做）

### 5.1 这台手碟的 9 个键是带八度的

| 位置 | 键 | 含义 |
|---|---|---|
| 上排 3 个 | `1̇ 2̇ 3̇` | 数字**上方带点** = 高八度 |
| 中排 5 个 | `3 4 5 6 7` | 不带点 = 中音区 |
| 下排 1 个 | `6̣` | 数字**下方带点** = 低八度 |

**中音区没有 1 和 2**，所以曲子里的 do、re 只能落在上排高八度键上；`3` 和 `6` 各有两个八度可选。
这意味着选键**必须同时用音级和八度**，只按音级映射会把所有 do 都点到同一个键上、旋律轮廓就没了。

`PadMapper` 的做法：
1. 以旋律的**最低音**为锚，算出它所在的 do 音高（`tonicFor`）——用最低音而不是中位数，
   是为了让一个正常八度的旋律完整落在乐器的八度窗口内，而不会被劈成两半；
2. 把每个音吸附到最近的**全音阶级数**，同时得到「音级 + 八度偏移」；
3. 在音级对应的候选键里，选八度最接近的那个。

所以 `E4 → 中音3`、`E5 → 高音3`、`A3 → 低音6`，而 `C4 和 C5` 都落在高音1上（乐器只有这一个 do）。

> **一个无法回避的乐器限制：** 中音区没有 `1` 和 `2`，所以曲子里的 do、re 会被抬到高八度键上。
> 例如《小星星》会弹成 `高音1 高音1 中音5 中音5 中音6 中音6 中音5 中音4 中音4 中音3 中音3 高音2 高音2 高音1`。
> 每个音的**音高本身是对的**（该是 C 就是 C），只是 do、re 落到了上面一排。这是手碟的键位结构决定的，
> 不是映射出错——换任何映射方案都无法避免，因为乐器只有一个 do 和一个 re。

如果关掉【按八度自动选键】，则所有音统一按中音区处理（1、2 仍只能落到高音键）。

### 5.2 调性映射：变化音就近吸附

手碟是全音阶乐器，所以任何乐曲都要先"改编"：按音级映射（C 调里 C=1, D=2, …, B=7），
**变化音吸附到最近的音级**（C 调里 F# → 4）。这是编曲上的正确处理——与其留个空拍，不如就近简化。

### 5.3 音频转谱为什么锁到低音（v1.3 修复）

YIN 是**单音**检测器。整首流行歌是混音，它会锁定"最强的那个周期信号"——实践中是**贝斯和底鼓**，
比主旋律低一到两个八度。实测一首真实中文流行歌（22050Hz，90 秒）：

| 分析频段 | 检出 | 音域 | 结果 |
|---|---|---|---|
| 65–2100 Hz（原设置） | 157 个音 | C2~F#4，平均 **G2** | 弹出来是**贝斯线**，不是主旋律 |
| **120–1000 Hz（v1.3）** | 35 个音 | B2~F#4 | 落在人声实际所在音区 |

120 Hz 把整个贝斯/底鼓区域滤在外面，同时仍容纳低音男声。合成单音旋律仍能正常检出，
静音/白噪声仍然返回 0 个音（负例对照没有被破坏）。

### 5.4 时间对齐

MIDI 的 tempo 变化会正确换算成毫秒；播放时再乘以【速度×】倍率。
音符间隔小于 60ms 的会被合并——`dispatchGesture` 的调度精度到不了更细。

### 5.5 校准为什么用悬浮窗而不是新开一个 Activity

直接盖在游戏上点，坐标就是屏幕真实坐标，不存在横竖屏、状态栏、导航栏导致的偏移。

### 5.2 调性：自动识别，不靠你手工试

选错调性不是"移调"那么简单——它会把每个音重新解释成不同的音级，整段琴键序列都会错。
所以导入文件后会**自动识调**（`KeyDetector`：每个音按音长和该音级在调内的稳定度投票给各个候选调，
再取总分最高的），直接填进下拉框。识别结果会显示在状态栏，不对可以手动改。

## 6. 已知限制

- **整首流行歌的音频转谱不可靠，这是本方案最大的短板。** 混音里的鼓、贝斯、和声会干扰单音检测，
  即使按 5.3 滤到人声频段，也只能抓到旋律的一部分。**要弹完整的流行歌，请用 MIDI（`.mid`）文件。**
  音频路径的定位是：单音哼唱、独奏乐器、或只要个大概。
- 音频最多分析 5 分钟（防止手机内存爆掉）。
- 依赖 `dispatchGesture`，**实测每次点击有几十毫秒级系统开销**，极快的十六分音符会不稳。

## 7. 重新构建

```bash
cd /data/data/com.termux/files/home/deepseek-harness-termux/handpan-app
./build.sh
```

`build.sh` 会自动下载 `android.jar`（首次，约 64MB）并生成签名密钥，然后走完整条：
`aapt2 compile → aapt2 link → javac → d8 → 打包(pack.py) → apksigner sign → 合规校验`。

> **关于 `pack.py`**：本机没有 `zipalign`。Android 11+ 要求 `resources.arsc` **不压缩**且 **4 字节对齐**，
> `AndroidManifest.xml` 也要不压缩——用普通 zip 工具重打包会把它们压掉，直接装不上。
> `pack.py` 按 zipalign 的规则做对齐；`pack.py verify` 会在每次构建末尾强制检查这条不变量，
> 防止以后改构建脚本时悄悄回归。单独校验已有 APK：
> ```bash
> python3 pack.py verify --apk handpan-autoplay.apk
> ```

纯离线测试（不构建 APK，直接跑算法模块）：

```bash
cd app/src && javac -d /tmp/x com/handpan/autoplay/*.java
```

## 8. 源码结构

```
handpan-app/
├── build.sh                     # 一键构建+签名脚本
├── pack.py                      # zipalign 等价的打包器 + 合规校验
├── handpan-autoplay.apk         # 产物
└── app/
    ├── AndroidManifest.xml
    ├── res/                     # 布局/文案/无障碍配置/图标
    └── src/com/handpan/autoplay/
        ├── MainActivity.java              # 单页 UI，串起全流程
        ├── HandpanAccessibilityService.java  # 注入手势（核心能力）
        ├── OverlayController.java         # 悬浮校准层 + 悬浮停止按钮
        ├── Playback.java                  # 实时调度器，按毫秒派发点击
        ├── MidiParser.java                # SMF 解析（tempo map/running status/SMPTE）
        ├── PitchDetector.java             # YIN 音高检测（音频→音符）
        ├── AudioDecoder.java              # MediaCodec 解码 / 手写 WAV 解析
        ├── JianpuParser.java              # 简谱文本解析
        ├── SongLoader.java                # 格式分发 + 单音旋律提取
        ├── ScaleMapper.java               # 音高 → 简谱音级 1~7
        ├── PadMapper.java                 # 音级+八度 → 9 个琴键中的哪一个
        ├── AppPrefs.java                  # 坐标与设置持久化
        └── RawNote.java                   # 音符数据类
```
